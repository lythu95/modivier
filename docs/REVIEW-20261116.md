## 一、总体评价

这是一个完成度很高、工程意识很强的项目。架构轻量清晰，注释普遍解释了"为什么这么做"而非"做了什么"，多处能看到对竞态、时序、平台差异的成熟处理。主要问题集中在：**一处明确的死代码、每击键触发的性能放大链、源码模式链接单击劫持**，以及若干健壮性/安全收敛建议。

### 做得好的地方

1. **分层清晰**：`lib/tauri.ts` 统一封装全部原生 API 并提供浏览器降级，`vite dev` 即可调试 UI；编辑器大依赖（Vditor / CodeMirror）懒加载分包 + 启动后预热，启动关键路径很轻。
2. **单一状态源**：`state.ts` 的 tabs + subscribe/notify 模型简单可控，脏检查逻辑（未命名标签只在有实质内容时才算脏）考虑周到。
3. **外部修改检测完善**：聚焦 / 标签切换 / 3s 轮询三通道 + 保存前 mtime 冲突确认 + 防对话框重入（`isDialogOpen`），形成闭环。
4. **模式切换定位**：editors.ts 的"内容锚 + 视口相对位置"方案（captureVditorAnchor/captureCmAnchor）解决往返漂移，是本项目最复杂的逻辑，实现细致。
5. **安全基线**：capabilities 最小化授权、Vditor `sanitize: true`、窗口隐藏创建避免尺寸闪现、Rust 侧 3 秒兜底显示。
6. **CI 成熟**：三平台矩阵、macOS 通用二进制、便携单文件、幂等 Release、Gitee 同步踩坑有记录。

## 二、问题清单

### 高优先级

#### H1. 快捷键处理存在重复分支（死代码）
[src/main.ts](../md_editor/src/main.ts) `setupShortcuts` 中 `key === 'f'` 的 else-if 分支出现两次且完全相同（约 L271-277 与 L278-284），第二个分支永远不会执行。属于合并/编辑残留，应删除其中一个。

#### H2. 每次击键触发一条"性能放大链"
`editors.ts` 的 input 回调每次输入都 `notify()`，而订阅方包括：

- [src/main.ts](../md_editor/src/main.ts) L182：`subscribe(() => onExternalCheck())` → 每击键都向 Rust 发一次 `stat_file` IPC（`fs::metadata`）。注释意图是"标签切换时核对"，但实际任何状态变化（含打字）都会触发。
- [src/ui/tabs.ts](../md_editor/src/ui/tabs.ts) L43-51：标签栏 `innerHTML = ''` 全量重建 + `scrollIntoView`，每击键一次。
- [src/main.ts](../md_editor/src/main.ts) L156：`updateLayout → activateEditor → focusActiveEditor()`，每击键对编辑器再 focus 一次；IR 模式下对 contenteditable 的 focus 调用有干扰 IME 的潜在风险。
- [src/ui/statusbar.ts](../md_editor/src/ui/statusbar.ts) L43：`Array.from(tab.content).length` 全文 O(n) 扫描，大文档下每击键一次。

建议：区分通知类型（如 `notify('content' | 'tabs' | 'active')`），外部修改检测只在 activeId 变化时触发；标签栏仅在结构/脏态变化时重建。

#### H3. 源码模式链接"单击即打开"，无法鼠标编辑链接
[src/cm-deps.ts](../md_editor/src/cm-deps.ts) L79-81：`mousedown` 命中链接正则即 `e.preventDefault()` 并打开。preventDefault 会阻止光标落位——**用户无法用鼠标点击链接文本内部进行编辑**，只能键盘绕行，且浏览源码时误触即跳走。建议改为 Ctrl/Cmd+Click 触发（与 Typora/VSCode 一致），mousedown 改成判断修饰键后再接管。

### 中优先级

#### M1. 浏览位置记忆的源码模式部分未实现
[src/positions.ts](../md_editor/src/positions.ts)：`DocPos.src` 字段注释为"源码顶行行号"，但 `savePosition` 恒写 `src: 0`，`loadPosition` 也只返回 `ir`。源码模式下打开文件不恢复位置。要么实现，要么删掉字段避免误导。

#### M2. 外部重载的滚动位置保留逻辑与其他两处不一致
[src/files.ts](../md_editor/src/files.ts) L239 `reloadTab` 直接取 `.vditor-ir` 的 scrollTop；而 [src/editors.ts](../md_editor/src/editors.ts) `irScroller` 与 [src/positions.ts](../md_editor/src/positions.ts) `irScrollTop` 都是"从 pre 向上找真正溢出的容器"。三处对同一问题的答案不一致，若真实滚动容器不是 `.vditor-ir`，外部修改重载后位置静默丢失（恢复为 0）。建议复用同一个 scroller 查找函数。

#### M3. 纯源码模式的标签页也会创建 Vditor 实例
[src/editors.ts](../md_editor/src/editors.ts) L116-176：`activateEditor` 无论 `tab.mode` 是什么都创建 Vditor（含 wasm/Lute 加载）。打开 .log/.json 等非 Markdown 文件（设计为源码模式查看）也要付出 Vditor 初始化成本。建议 IR 实例延迟到首次切到 IR 模式时再创建。

#### M4. asset 协议作用域过宽 + 相对路径可 `..` 逃逸
[src-tauri/tauri.conf.json](../md_editor/src-tauri/tauri.conf.json) L31：`assetProtocol.scope: ["**", "**/*"]` 允许 webview 读取磁盘任意路径；[src/images.ts](../md_editor/src/images.ts) `joinPath` 会消费 `..` 段。一篇不可信 Markdown 里的 `![](../../../../sensitive/file)` 会被改写为 asset URL 加载。`sanitize: true` 已大幅降低 XSS 外泄风险，但建议：scope 收敛或在 rewrite 前校验解析结果（如限制常见图片扩展名 / 记录已允许目录）。

#### M5. CSP 中 `script-src` 含 `'unsafe-eval'`
同文件 L28。wasm 只需要 `'wasm-unsafe-eval'`；`'unsafe-eval'` 若是为某个依赖保留，建议注释说明来源并定期复验能否移除。

#### M6. GBK 文件保存时静默转码为 UTF-8
[src-tauri/src/lib.rs](../md_editor/src-tauri/src/lib.rs) `write_file` 统一写 UTF-8 无 BOM；`encoding` 字段注释"仅用于展示"。用户编辑 GBK 文件保存后，其他 GBK 工具打开将乱码，且保存后 `tab.encoding` 不更新（显示与磁盘事实不符）。建议：保存非 UTF-8 来源文件前提示一次，或按原编码写回（encoding_rs 已具备编码能力）。

## 三、其他观察（非问题）

1. **无自动化测试**。核心纯函数适合抽出单测：`parseOutline`、`normalizeForMatch`/`findLineByNeedle`、`gfmSlug`、`joinPath`、`cleanHeadingText`。这些是回归高发区。
2. **版本号三处手工同步**（package.json / tauri.conf.json / app-info.ts）。可用 Vite `define` 从 package.json 注入 `APP_VERSION`，消除一处。
3. **i18n 字典**四语言 key 已人工核对齐全；`vditorLang` 的 `'jp'` 与 Vditor 实际语言包名建议注释确认。
4. **Cargo.toml** 可补 `rust-version` 字段；`winreg 0.52` 有更新版本（0.5x），非紧急。
5. **release.yml** 中 macOS 便携单文件提示需去除 quarantine，README 已覆盖，链路完整。

## 四、结论

代码质量整体在"可发布"水准之上：无类型错误、无安全高危项、边界场景大多有注释级的思考记录。建议优先处理 **H1（死代码）**、**H3（链接单击劫持）** 两个确定的行为问题，以及 **H2（击键放大链）** 这个在大文档下会实际感知的性能问题；中优先级各项可按版本节奏排期。
